# Blender 8K 透明线稿渲染流程模板

版本：1.0 · 更新：2026-11-09 · 已验证环境：Windows、Blender 5.2.3 LTS。

适用于机械模型、道具、整机及拆分部件。输入优先使用已整理的 FBX；也可从 Blender 工程中明确隔离目标后制作静态渲染副本。先出少量测试图确认，再运行完整批次。

## 1. 交付标准

| 项目 | 标准 |
|---|---|
| 原生分辨率 | 7680 × 4320，分辨率百分比 100% |
| 图片格式 | PNG，RGBA，透明背景，黑色线条 |
| 主渲染引擎 | EEVEE；Freestyle 用于提取线条，不是独立主引擎 |
| 合成 | 只输出 Freestyle 通道，避免输出模型材质、灯光和阴影 |
| 单模型完整套数 | 4 套，每套 14 角度，共 56 张 |
| 预览 | 另做白底 JPG，不能用预览替代透明原图 |
| 包装 | 按套装、模型分目录；可合并一个 ZIP，完成后做 CRC 检查 |

四种效果：

1. 正交实线：没有近大远小，用于形体、三视图和结构对照。
2. 常规透视实线：50 mm 相机，用于斜向展示。
3. 正交结构虚线：可见实线叠加被遮挡的结构虚线。
4. 常规透视结构虚线：透视展示叠加内部结构虚线。

“结构虚线”显示模型中实际存在但被遮挡的边，不会自动推导不存在的内部零件，也不等于剖切图。

## 2. 每次任务先填写

```yaml
任务名称: 新模型线稿
输入文件:
  - D:/Models/model_01.fbx
  - D:/Models/model_02.fbx
输出目录: D:/Renders/新模型线稿
测试方案:
  效果: [正交实线, 正交结构虚线]
  角度: 左前_俯视45
完整批次:
  每个模型角度数: 14
  套数: 4
  是否已经确认测试图: false
  是否合并压缩包: true
  是否保留源模型: true
```

数量公式：`模型数 × 效果套数 × 角度数`。例如 3 个模型、2 种效果、1 个测试角度为 6 张；3 个模型的完整四套为 168 张。

“先出两套测试”优先确认是两种效果各一张，还是两种效果的全部角度。没有确认测试前，不自动扩大成完整批量任务。

## 3. 输入检查与模型隔离

1. 确认准确路径、扩展名、修改时间和文件大小，保留原文件。
2. 非零字节不代表有模型。FBX 导入成功后仍要检查求值后的网格数量、顶点数量和包围盒。曾出现约 4 KB 的 FBX 能导入，但没有任何几何体。
3. 不以 Blender 进程退出码单独判断成功：Python 脚本报错时，进程仍可能返回 0。还要检查导入报告、任务清单与目标图片。
4. 多个 FBX 按各自导出内容独立处理；不同形态、姿态不合并，也不通过文件名猜测需要删除哪些零件。
5. 从 `.blend` 导入时，先排除人物、背景、备用件与重复实例，尊重集合的渲染开关。集合实例必须使用实例的世界变换，不能只看对象列表中的局部网格。
6. 在当前姿态上求值修改器、骨架和实例，形成静态渲染副本。保留每个零件相对位置，不修改原模型文件。
7. 输出一张灰模检查图，并记录模型名、源路径、顶点数、包围盒及源帧。发现零件漂浮、姿态异常、错误背景或漏件时先确认，不擅自修复装配。

推荐记录源文件 SHA256；至少保存文件大小、修改时间和导入报告。换源文件、换姿态或换参数时使用新任务目录，避免把旧图片当作新结果复用。

## 4. 空间与相机

### 4.1 归一化

将目标所有求值网格的世界包围盒合并，以包围盒中心为取景中心。渲染副本可将最长边统一缩放到 2 个场景单位，解决手表与大场景单位差异过大造成的数值和裁剪问题。

记录平移和缩放因子。该归一化只服务出图，原始尺寸保持在源文件中；不同模型的出图尺寸不能直接用来推断真实物理尺寸。

### 4.2 标准 14 角度

| 编号 | 名称 | 相机所在方向，指向模型中心 |
|---|---|---|
| 01 | 前 | `(0, -1, 0)` |
| 02 | 后 | `(0, 1, 0)` |
| 03 | 左 | `(-1, 0, 0)` |
| 04 | 右 | `(1, 0, 0)` |
| 05 | 上 | `(0, 0, 1)` |
| 06 | 下 | `(0, 0, -1)` |
| 07–10 | 左前、右前、左后、右后，俯视45° | `(x/√2, y/√2, +1)` |
| 11–14 | 左前、右前、左后、右后，仰视45° | `(x/√2, y/√2, -1)` |

四个平面方位依次为 `(-1,-1)`、`(1,-1)`、`(-1,1)`、`(1,1)`；使用方向前先归一化。

直接使用 `(±1, ±1, ±1)` 的仰俯角约为 35.3°，并不是 45°。前后左右按导入后的世界轴定义，不自动等于模型设计上的“正面”；如需语义正面，先确认模型朝向。

### 4.3 相机拟合

- 相机局部 `-Z` 指向中心，局部 `Y` 作为上方向。
- 同一模型所有正交图使用同一 `ortho_scale`；所有透视图使用同一焦距和中心距离。
- 透视基准为 50 mm，传感器宽 36 mm，`sensor_fit = HORIZONTAL`。
- 检查 14 个相机投影后共同增大正交比例或透视距离，直到全部角度都能容纳目标。当前脚本拟合到约 86% 的画幅边界范围。
- 再检查所有包围盒角点位于画面内部；验证范围为归一化坐标 `0.02 < x,y < 0.98`，且深度位于近远裁剪面之间。
- 统一模型最长边为 2 后，当前脚本近裁剪为 0.001，远裁剪为模型包围球半径的 100 倍。没有归一化时必须重新计算，不能直接照搬。

这些是包围盒检查，弧形和细长模型可能仍有较多留白；它有利于统一尺度与防止裁切。特殊展示构图可另建相机，不覆盖标准对照相机。

## 5. 已确认的 8K 取线参数

| 参数 | 数值 |
|---|---|
| Freestyle 选择模式 | Editor / 参数化线条集 |
| 以通道输出 | `as_render_pass = True` |
| 折痕角 | 145° |
| 面平滑影响 | `use_smoothness = False` |
| 笔画链 | `use_chaining = True` |
| 按最短/最长笔画过滤 | 均关闭，避免短细节和边缘被误删 |
| 全局线宽 | Absolute 模式，倍数 1 |
| 轮廓 | 5.4 px，不透明度 1，黑色，圆端点 |
| 可见结构 | 3.2 px，不透明度 1，黑色，圆端点 |
| 近层遮挡结构 | QI 1–2；2.8 px；不透明度 0.75；虚线 16 px / 间隔 12 px |
| 深层遮挡结构 | QI 3–8；2.2 px；不透明度 0.45；虚线 12 px / 间隔 16 px |

线条集建议独立命名：

| 线条集 | 可见性与边类型 |
|---|---|
| `01_轮廓` | VISIBLE：Silhouette、Border、Contour、External Contour |
| `02_结构` | VISIBLE：Crease |
| `03_近层结构` | RANGE QI 1–2：上述轮廓边及 Crease |
| `04_深层结构` | RANGE QI 3–8：上述轮廓边及 Crease |

各边类型采用 OR。两套“实线”关闭 03/04，另外两套开启。QI 是 Freestyle 的遮挡数量判定范围，不等同于实际零件数量。

线宽与虚线间距已经按原 1080p 基准放大 4 倍，属于 8K 最终像素参数。不要在 8K 上再乘一次 4。换输出分辨率时，如需保持相对视觉粗细，应统一缩放线宽、虚线长度和间隔。

## 6. 只输出透明线稿

1. 主引擎设为 `BLENDER_EEVEE`，开启 `render.use_freestyle`。
2. 开启 `film_transparent`，设 PNG、RGBA、7680×4320、100%。
3. 在视图层开启 Freestyle，并以独立通道输出。
4. 在合成中将 Render Layers 的 `Freestyle` 输出接到最终 Image 输出，不连接材质渲染的 Combined 通道。
5. 使用 Standard 视图变换作为当前配置的一部分。

当前脚本采用 Blender 5.2 的 `compositing_node_group` 接口。其他版本的合成节点 API 可能不同，需要先做小图验证。

空白 `.blend` 模板只保存取线与合成设置。新模型应运行准备脚本重新生成并拟合 14 相机，而不是直接沿用空模板内的示意相机。

## 7. 最小可复用命令

仓库中的 `scripts/prepare_fbx.py`、`scripts/render_one.py` 对应已实际验证的本地模板脚本。两者运行在 Blender 自带 Python 中；校验脚本运行在安装 Pillow 的普通 Python 中。

PowerShell 示例，路径需要按当前机器填写：

```powershell
$BlenderExe = 'D:\Program Files\Blender Foundation\Blender 5.2\blender.exe'

# 建立渲染副本、14相机、4种测试任务和灰模检查图
& $BlenderExe --factory-startup --disable-autoexec -b -t 8 --python '.\scripts\prepare_fbx.py' -- 'D:\Models\model.fbx' 'D:\Renders\model_test'

# 测试任务0：正交实线；任务2：正交结构虚线
& $BlenderExe --factory-startup --disable-autoexec -b -t 8 --python '.\scripts\render_one.py' -- 'D:\Renders\model_test\渲染任务.json' 0
& $BlenderExe --factory-startup --disable-autoexec -b -t 8 --python '.\scripts\render_one.py' -- 'D:\Renders\model_test\渲染任务.json' 2

# 检查本次选择的两张测试图
python '.\scripts\verify_outputs.py' 'D:\Renders\model_test\渲染任务.json' --indices 0 2
```

任务 1 为常规透视实线，任务 3 为常规透视结构虚线。准备脚本生成 4 个测试任务，每个任务默认使用左前俯视45°相机。

`profiles/8k-lineart.json` 是可追溯的参数记录；现有准备脚本的实际参数写在代码常量中，不会自动读取该 JSON。修改风格时必须同步修改脚本与记录，并用新输出目录重新测试。

## 8. 测试确认后建立完整清单

对每个模型、每个选择的效果、每个标准角度建立一条任务，至少包含：

```json
{
  "model": "model_01",
  "variant": "01_8K正交_实线",
  "blend": "D:/Renders/model_test/工程/model_01_14相机.blend",
  "scene": "model_01_线稿",
  "camera": "model_01_07",
  "perspective": false,
  "hidden": false,
  "ortho_scale": "准备脚本算出的数值",
  "distance": "准备脚本算出的数值",
  "radius": "准备脚本算出的数值",
  "output": "D:/Renders/full/01_8K正交_实线/model_01/model_01_07_左前_俯视45.png"
}
```

上面的三个取景参数必须用准备任务中的实际数值，不是字符串。相机名按 `_01` 至 `_14` 选择；输出文件名同时包含模型、序号和角度。

可以复用已经确认、参数和构图一致的测试原图；只做无损复制，不能拿 JPG、放大图或旧参数结果充数。当前便携脚本提供准备与单张渲染入口；大批量由外部控制器展开任务清单、调度、校验和打包，不能把“已生成测试清单”误报为“完整批次完成”。

## 9. 批量渲染与断点恢复

已采用的可靠做法：

1. 一个模型的一套角度作为一组，读取一次渲染副本后连续渲染，减少反复载入大工程。
2. 并行起点为两个独立 Blender worker，每个 8 CPU 线程。这是当前设备的已验证配置，复杂模型可先改单 worker；不要无上限并发。
3. 先写 `文件名.rendering.png`，等 `render(write_still=True)` 返回，再在同一目录用原子替换发布最终 `.png`。
4. 控制器只读取最终文件名，不能把正在写入的临时 PNG 当作完成文件。
5. 进度和校验 JSON 也使用临时文件加原子替换，防止浏览器或控制器读到半个 JSON。
6. 先逐项复查已有结果，再跳过验证通过的图片。每组失败最多再试一次，仍失败则记录具体模型、套装、角度和日志。
7. UI 显示“已验证张数 / 总张数”和当前模型/角度；Freestyle 没有可靠的单图内百分比，不伪造当前图片进度。
8. 关闭进度页面不会停止 worker。修改清单、清理工程或重新开任务前，检查旧控制器和 worker 是否仍在运行。

实际修复过的问题：校验器曾抢先读取尚未写完的 PNG，抛出 `SyntaxError: broken PNG file`，导致进度停住。除原子发布外，读取异常至少处理 `OSError`、`ValueError`、`SyntaxError`、`EOFError`，并对暂不可读的文件稍后再查，不能让单张读取异常直接杀死整个批次。

修改参数或源文件后必须新建任务输出目录；已有校验标记不是跨参数版本可复用的证明。

## 10. 每张图片与最终包的检查

- 文件可以完整解码，实际尺寸为 7680×4320。
- 模式为 RGBA，Alpha 最小值为 0、最大值大于 0，非透明包围盒非空。
- Alpha 检查只能排除空图、全不透明图，不能代替视觉检查。还要看灰模与线稿，确认模型正确、没有裁切、漏件和异常密集线。
- 白底预览先把 RGBA 缩小，再合成白底，避免再创建完整 8K 白底画布占用内存。
- 按模型、套装统计预期数量；每个模型每套应有 14 个角度，文件名唯一。
- 生成 14 角度总览，原始 PNG 不改色、不降分辨率。
- ZIP 先写临时名称，检查 PNG 数量并运行 `ZipFile.testzip()`，CRC 正常后再发布最终名称。
- 所有图片通过、打包通过后才标记 `Complete`。失败时保留错误清单，不发布冒充完整结果的压缩包。

## 11. 常见问题

| 现象 | 检查与处理 |
|---|---|
| 透明PNG在某些预览器里全黑 | 黑线叠在黑色预览背景上；先用白底预览确认 Alpha 和图像内容 |
| 线稿发脏、线条过密 | 检查重复几何、重叠表面、Crease取线、隐藏QI范围；优先降低隐藏线强度或范围，并先出测试 |
| 轮廓或边缘断线 | 确认轮廓边类型开启，链连接开启，最短笔画过滤关闭；仍异常再查网格、裁剪和投影，不靠单纯加粗掩盖 |
| 整图有材质阴影 | 合成连接了Combined而非Freestyle通道 |
| 细小零件消失 | 检查源导出是否包含该零件、求值实例是否正确、视图层/集合隐藏及线条过滤 |
| 脚踏板、组件漂浮 | 先核对FBX导出姿态、父级与修改器；未经确认不移动原零件 |
| 空FBX但有文件大小 | 导入后检查实际顶点和网格，重新导出；不要未经确认换成同目录另一个相似文件 |
| 批次停在某个张数 | 同时看控制器、worker、日志、文件修改时间和已验证数量；区别单图耗时、校验异常与进程已结束 |
| 内存或显存不足 | 减少并行worker，保持8K原生输出；不要静默降成4K后放大 |
| 模型比例和朝向不对 | 核对FBX轴、单位和世界变换；每个模型重新拟合相机 |

## 12. 归档与清理

优先保留：原始模型、最终 PNG、最终压缩包、参数 JSON、流程 MD、通用模板与脚本。原始模型已找不到时，保留至少一份含模型的渲染副本，不能把唯一模型数据当作临时文件删除。

可在确认任务完成后清理：已被验证为重复的工程、旧错误版本、临时图、大日志、可由源模型重新建立的专用渲染副本。

清理前确认没有活动任务，核对删除目标的绝对路径都位于指定工程目录；不同模型/套装不能仅凭相同文件大小判定重复。重复图片用 SHA256 比对，重要工程可比对几何数据并保留一份模型备份。

最终 PNG 与 ZIP 是独立交付物，不依赖 `.blend` 才能打开；`.blend` 仍对修改旧模型、补角度、补图有价值。
